# 三角洲行动 · 口琴自动演奏器

把一份文本简谱按时间轴送进游戏里的口琴界面。桌面应用（Qt 6 / QML + C++），
按键走 Windows 的 `SendInput` —— 不读内存、不注入进程。

## 注意事项

- **默认键位来自S11版本。** 口琴界面的键位可能随版本变化，
  也可能改过绑定，首次使用请先跑一次校准。
- **反作弊风险自负。** 模拟输入不碰内存，通常比注入式外挂安全得多，
  但反作弊对自动化输入并非完全无感知，封号风险无法归零。
- **本程序要管理员权限。** 游戏通常以管理员运行，而 Windows 的 UIPI 会静默丢弃
  低权限进程发往高权限进程的输入 —— 不给权限的表现是「一声不响，游戏毫无反应」。
  清单里写的是 `requireAdministrator`，**启动时**由 Windows 弹 UAC 提权，
  不需要进了界面再点按钮重启。代价是每次启动都会弹一次 UAC。

## 开发

需要 MSVC（Visual Studio 的 C++ 生成工具）和 Qt 6（带 `msvc2022_64` 套件）。
Qt 自带的 CMake 与 Ninja 就够，不用另装：

```bat
:: 先调用 vcvars64.bat 进 MSVC 环境（或用开发者命令行）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug ^
       -DCMAKE_PREFIX_PATH=D:/Qt/6.11.2/msvc2022_64
cmake --build build
ctest --test-dir build --output-on-failure
```

直接跑测试程序也得让 `Qt6Core.dll` 在 PATH 上；CMake 已经把 Qt 的 bin 目录写进了
每条测试的 `ENVIRONMENT`，从任何 shell 跑 `ctest` 都不用手工设。

两个和构建配置绑在一起的决定：

- **Debug 是控制台程序，Release 才是 GUI 程序。** QML 的报错只有 stderr 这一条通道，
  而 GUI 子系统收不到 —— 调试期没有控制台，`ApplicationWindow is not a type` 这类
  错误就表现为「程序起来了但屏幕上什么都没有」。
- **发布要单独配一个 Release 目录**（`-B build-release -DCMAKE_BUILD_TYPE=Release`），
  打包前 `windeployqt --release build-release\app\harmonica-player.exe`。
  部署完之后把 Qt 从 PATH 上摘掉再跑一次，起来了才叫产物自足。

**为什么是 MSVC**：换掉 GNU 工具链（WinLibs）是因为它会把自己的
`default-manifest.o` 无条件塞进链接命令（specs 里 `%:if-exists(...)`，没有开关能关），
而 GNU ld 不合并清单 —— 于是 exe 里同时躺着两份同 ID 的 `MANIFEST`：
本项目那份 `requireAdministrator` 和 WinLibs 那份 `asInvoker`。UAC 取哪一份取决于
链接顺序，改图标、加减资源、升级工具链都可能让顺序反过来，然后程序**静默地不提权**
（比报错难查得多）。以前是靠把工具链里那个文件改名处理的，动的是整个工具链。
MSVC 的链接器会正确合并清单，这条路径整个消失。轮②落地时会用 dumpbin 复核
产物里只有一份清单、且是 `requireAdministrator`。

清单还是用 `app/app.manifest`，但不是靠链接器选项：CMake 会在链接命令**末尾**补一个
`/MANIFEST:NO`，而 `link.exe` 后写的生效，所以 `/MANIFEST:EMBED` + `/MANIFESTUAC:...`
那条路会被静默盖掉（表现是清单没嵌进 exe，提权只存在于旁边那个 `.exe.manifest` 文件里，
单独把 exe 拷走就失效）。现在的做法是配置期按构建类型生成清单、构建末尾用 `mt.exe`
写进 exe 的 `#1` 资源 —— 有且只有一份。实测：Debug 产物 `asInvoker`，Release 产物
`requireAdministrator`（`mt -inputresource:exe;#1` 能取出来，`#2` 不存在）。

⚠️ `mt.exe` 的参数是 `文件;#1`，这个分号加井号在 CMake/Ninja/cmd 三层里都会被吃掉一层，
所以构建里是配置期写一个一次性批处理来调它（见 `app/CMakeLists.txt` 那段注释）——
别再试着把它写成 `target_link_options` 或 `VERBATIM` 参数。

### 曲谱目录

启动时会检查程序同目录下这三个目录，缺了就建出来：

```text
songs/
  dhs/                        演奏谱，曲库扫这里
  numbered_musical_notation/  编辑器工程（.score.json）
```

程序根目录**就是 exe 所在目录**，不往上找 —— 配置和曲谱只认程序旁边这一份，
装到哪就是哪。所以开发时跑 `build/` 下面那个 exe，读写的也是那个目录，
不会摸到仓库根目录去。仓库里 `songs/dhs/` 那四首示例谱因此不会自动出现在
开发用的曲库里，要看得把它们拷到 exe 旁边那一层（`build/app/songs/dhs/`）。

装在 `Program Files` 下面的时候，非管理员进程没有写权限，目录可能建不出来 ——
那种情况曲库会显示「目录不可用」和具体原因，程序照常启动。

### 社区曲库

曲库页有「本地曲库 / 社区」两档切换。社区那档从
`https://harmonica-songs.pages.dev/manifest.json` 拉清单：

```json
[
  {
    "song_title": "鸟之诗",
    "dhs_URL": "dhs/鸟之诗.dhs",
    "dhs_sha256": "…",
    "nmn_URL": "numbered_musical_notation/鸟之诗.score.json",
    "nmn_sha256": "…"
  }
]
```

- `dhs_URL` / `nmn_URL` 是相对清单的路径，拼接时以清单地址为基准
- **列表显示歌名和时长，但时长不是清单里的字段**：它得把 `.dhs` 读进内存，
  交给 core 里**同一个解析器**算出来。界面上的时长得和真吹时的时长一致，
  不许在界面那边另写一套

**试听**的发声不属于演奏路径：

- 演奏只负责按键，实际的声音是游戏里的口琴发的；试听是离线预览，属于界面层。
  但**时值仍然只有 core 那一份** —— `core/preview.h` 折算出「从曲首算起的时间 +
  半音数」，界面只管把半音数换成频率排进音频时钟。音高按简谱常规读法折算
  （度数走大调音阶、`#` 加半音、音区按八度平移），**只用于试听**，演奏路径不看这个值
- Rust 版把发声甩给浏览器，是因为标准库没有音频、为「听个大概」引一套音频栈不划算。
  Qt 自带 `QAudioSink`，轮③ 会把合成收回 C++：少一层跨语言边界，
  也不可能多出一条看起来像演奏路径的东西

下载与校验都在 C++：`QNetworkAccessManager` 拉清单和谱子，`QCryptographicHash` 算
SHA-256。核对的是**拿到的原始字节** —— 先按文本解码再编码回去，算出来的是「文本的哈希」
而不是「文件的哈希」，BOM 和换行都能把它改掉（下面那条事故就是这么来的）。
清单里没有 `sha256` 的条目不下载；两个文件都核对通过才落盘，
任一失败都不落半份（写第二个失败会把第一个删掉）；覆盖本地同名曲目前必须显式确认。

**下载**：两个文件都拿到、都核对过 `sha256` 才落盘，`.dhs` 进 `songs/dhs`，
简谱工程进 `songs/numbered_musical_notation`。

- 校验不过就重下一次，重下再不过才报「下载错误」；网络出错也一样报下载错误
- **本地已有同名曲目时会先问一句**（「继续下载会覆盖它」），取消或继续 ——
  覆盖是直接盖掉的，没有后悔药，所以这一步必须显式确认
- 两个文件任何一个出问题都**不落盘**：校验在前端做，后端只在两个都通过之后才被调用；
  万一写第二个失败，会把第一个删掉，尽量不留半份
- 摘要用 Qt 的 `QCryptographicHash`，不是自己写的实现 —— 以前「后端自己写 SHA-256
  怕敲错常量」的顾虑是 Rust 那边没有现成实现，现在不存在了
- 清单里没有 `sha256` 的条目不下载 —— 来历不明的东西不往盘上写
- 算哈希必须用原始字节（`arrayBuffer()`），不能用 `text()` 再编码回去：
  BOM、换行、编码都可能在中途变样，那样算出来的是「文本的哈希」而不是「文件的哈希」
- 界面上失败只显示一句「下载错误」，具体原因（哪个文件、期望/实际哈希）进控制台 ——
  一句话够用户判断怎么回事，细节留给排查的人

#### 清单里的 sha256

⚠️ **必须按「线上实际提供的那串字节」算。** 2026-09-17 出过一次八个文件的哈希
全部对不上、而文件本身完全正常：换行符差异（Windows 检出是 CRLF，
git 和 Pages 上是 LF）就足以让哈希完全不同。症状是下载永远报「下载错误」。

### 为什么不用 MinGW 构建（这段是历史，别改回去）

WinLibs 的 GCC 会把自己的 `default-manifest.o` 无条件塞进链接命令，GNU ld 又不合并清单，
实测某个 release 产物的 PE 资源里同时躺着两份同 ID 的 `MANIFEST`：

```text
MANIFEST.1   1822 字节   requireAdministrator   ← 本项目那份，排在前
MANIFEST.1    599 字节   asInvoker              ← WinLibs 那份
```

UAC 当时弹了，只是因为 Windows 二分查到了排在前面那份。资源顺序由链接顺序决定，
改图标、加减资源、升级工具链都可能让它反过来 —— 然后程序**静默地不提权**。
当时的处理是把工具链里那个文件改名（`.bak`），代价是影响整机所有用这套工具链的项目，
升级后还会被装回来。这就是现在改用 MSVC 的原因，见「开发」一节。
上游报成了 binutils bug 34362。

（注：改名这件事对本项目已经无关，但机器上别的走 `x86_64-pc-windows-gnu` 的
Rust 项目仍然依赖那个 `.bak`。）

### 演奏时的窗口

程序有两个窗口：

- **主窗口**：曲库、编辑器、设置。标题栏是**系统原生的**，只用 DWM 把颜色染成
  应用自己的底色（`DWMWA_CAPTION_COLOR` / `DWMWA_TEXT_COLOR` / `DWMWA_BORDER_COLOR`），
  所以看起来和窗口内容连成一体，但最小化/最大化/关闭按钮、拖拽、贴边、双击最大化
  全都是原生行为 —— 没有自己画标题栏，也没有碰 `WM_NCCALCSIZE`。
  这几个属性是 Windows 11（build 22000）才有的，Win10 上会自动退化成系统深色标题栏
- **悬浮窗**：演奏时浮在游戏上面那条，无边框、置顶，并且带 `WS_EX_NOACTIVATE` ——
  **点它不会把焦点从游戏抢走**。这条是刚需：焦点一旦离开游戏，后面的音就全废了

曲库页工具栏上有个「显示悬浮窗」按钮，就是用来验这条性质的。

### 单实例

同一时间只跑一个 —— 抢 `Local\com.deltaforce.harmonica-player` 这个命名互斥体，
抢不到就说明已经有一个在跑：把它的主窗口叫到前面（按窗口标题找），然后自己安静退出。
用互斥体而不是锁文件，是因为进程被杀掉时系统会自动释放，不会留下要人清理的残留。

### 托盘

通知区域有个托盘图标，用的就是应用图标本身：

- **右键**：菜单 →「显示主窗口」/「退出」
- **左键单击**：把主窗口叫到前面。托盘图标默认左键也弹菜单，这里要显式关掉
- **关掉主窗口不是退出**：窗口收进托盘（`CloseRequested` 被拦下、改成 `hide`）。
  不拦的话窗口会被真的销毁，而进程还活着，托盘的「显示主窗口」就再也没窗口可显示了。
  **要真正退出用托盘菜单里的「退出」** —— 它会先释放所有按键再结束进程，
  退出路径不能漏这一步，鼠标键卡在按下状态会让整个系统点不动。

**「把窗口叫到最前面」这件事没有哪一步单独靠得住**，所以 `win32::force_foreground`
连着做三步：`ShowWindow(SW_RESTORE)` 还原 → 先置顶再取消置顶（Z 序不受
「防抢焦点」规则管辖，这一步保证窗口一定露出来）→ 再抢前台
（`SetForegroundWindow` 在调用者不是前台进程时会被静默拒绝，所以先
`AttachThreadInput` 共享前台身份，万一还不成再用 `SwitchToThisWindow` 兜一次）。
三处都是 `let _ =`，尽力而为，失败了也不该炸掉程序。

### 热键

| 键 | 作用 |
| --- | --- |
| F9 | 开始 / 重播当前选中的曲目 |
| F10 | 立即停止 |

全局热键是演奏时唯一靠得住的控制方式 —— 那时候焦点在游戏里，界面上的按钮点不到。
注册失败（被别的程序占用）只在控制台报一句，悬浮窗上的按钮照样能点。

### 演奏链路

选中曲目后点「演奏」：**倒数 3 秒**（悬浮窗同步显示，给玩家时间把窗口切回游戏），
然后把谱子交给 core 的 `play` 在**独立线程**里跑。

- 起播前会重新读一遍 `harmonica.ini` —— 改完键位和时序不用重启
- 倒计时里随时可以取消（F10 / 悬浮窗上的停止）
- 已有一场在跑时再按 F9 = 重播：先停掉旧的那场再起新的，
  收工路径（`ReleaseGuard`）保证所有按键都被放干净，谁收尾都不会留下卡住的键
- **干跑**走同一条时间轴，但不发送任何输入 —— 用来核对动作表和节奏，不碰游戏。
  干跑不倒数（不用切回游戏）
- 进度是演奏线程里的一颗原子数（权威值），悬浮窗每 100ms 读一次，
  显示曲子剩余时间；事件只负责「开始了」「结束了」这两个状态切换
- 悬浮窗上的停止按钮和 F10 走同一条路：先停线程，按键由收工路径统一释放

**修饰键的交接规则**（2026-09-17 修过）：换段落时**旧的修饰键必须先松、新的才能按**。
游戏按事件逐个处理，新的按下时旧的还没松，它就会同时看到两组修饰键
（比如 左键+右键），那一段的音高判定会作废。所以修饰键的使命到本段最后一个音的
键松开就结束，同刻时先松音符键、再松旧修饰键、最后按新修饰键。

时序逻辑仍然只有 core 那一份：界面层的演奏控制器（轮③）只负责起线程、
传「停」、报进度，**不计算任何时间**。

### 键位校准

「开始校准」把 44 个音位**按顺序各输入一遍**：
不修饰 → +半音 → 降调 → 降调+半音 → 升调 → 升调+半音 → 升调+逗号 → 升调+半音+逗号，
每组从简谱 1 吹到 7（超高音只有 do）。设置页里那张「共 44 个音位」的表就是它。

它和演奏走**同一条** `build_actions` 管道 —— 修饰键的提前量、合并、松开顺序
与正式演奏完全一致，校准时听着对，演奏就对。core 里的 `calibration_song()`
只是把这 44 个音包成谱子的形状，好复用这条管道，不是什么乐谱。

校准进行中，设置页会显示当前吹到第几个音位、是什么组合、实际按哪些键 ——
音位的按下时刻取自动作表里的第 K 个 KeyDown，不在界面里算时间。

## 打包（Inno Setup 7）

安装包脚本是 `installer/harmonica-player.iss`，版本号不在里面写死，
由命令行 `/DAppVersion=` 传（取 `CMakeLists.txt` 的 `project(... VERSION)`）。

```bat
:: 1) Release 构建：提权清单由 mt.exe 嵌在 exe 里，跟着 exe 走
cmake -S . -B build-release -G Ninja -DCMAKE_BUILD_TYPE=Release ^
       -DCMAKE_PREFIX_PATH=D:/Qt/6.11.2/msvc2022_64
cmake --build build-release

:: 2) 暂存一份干净目录（别直接打包 build-release 目录，里面混着 CMake 中间产物）
copy build-releasepp\harmonica-player.exe  build-install\stagingxcopy /e /i build-releasepp\Harmonica      build-install\staging\Harmonica
windeployqt --release --no-translations --compiler-runtime ^
            --qmldir app\qml build-install\staging\harmonica-player.exe

:: 3) 出安装包（在开发者命令行里，让 windeployqt 认得到 VC 运行库）
"D:\Program Files\Inno Setup 7\ISCC.exe" /DAppVersion=0.3.0 installer\harmonica-player.iss
```

两个坑都踩过，别再省：

- **`--qmldir app\qml` 不能省。** 我们的 QML 是编进 exe 资源的，windeployqt
  只扫二进制时认不全 `QtQuick.Controls` 的样式模块；少了
  `qml\QtQuick\Controls\Fusion` 和那几个 `Qt6QuickControls2*.dll`，
  装完的程序会起一个白屏窗口。
- **`Harmonica\` 目录必须和 exe 放在一起。** 少了它启动直接报
  `Module "Harmonica" contains no type named "Main"`。
  验证办法：把 `Qt` 从 `PATH` 上摘掉再跑暂存目录里那个 exe，起得来才算部署完整。

`--compiler-runtime` 会把 `vc_redist.x64.exe` 放进暂存目录（要在开发者命令行里跑才拷得到）；
安装包把它下到临时目录、注册表里查到已装就跳过，不会往 `{app}` 里塞。
卸载**不会**删运行时长出来的 `harmonica.ini` 和 `songs\` —— 那是用户的东西。


## 简谱编辑器

点按钮或敲键盘录入音符，所见即所得，最后导出成 `.dhs`。

> 这一节是编辑器的规格，桌面版已经照着实现（`app/scoredoc` 是算法，
> `app/editorcontroller` 是编辑操作，`app/qml/EditorPage.qml` 是界面）。
> 两条实现方式换掉了：**试听**用 `QAudioSink`（不再依赖浏览器合成音）；
> **自动保存**落在程序自己旁边的 `autosave.score.json`（不再是 localStorage，
> 关程序时写、下次开自动恢复）。原来那份单文件网页版 `简谱编辑器.html`
> 已随 Tauri 版一起删除，git 历史里还能翻到。

- **时值**：四分 / 八分 / 十六分 / 三十二分，可加附点。
  减时线按简谱的写法连写：同一拍内、层数相同的相邻音符共用一条线，跨拍或跨小节断开
- **八度**：低音（数字下方一点）/ 中音 / 高音（上方一点）/ 超高音（上方竖排两点）
- **升号**；休止符按 `0` 键输入
- **增时线**：按「延长一拍 -」或键盘 `-`，音符右边长出横杠，表示这个音再延长一拍
- **连音线**：点「连音线」，再点一个音作起点，然后点终点。同一个音可以连多个目标
  （比如一个 `7` 既连后面的 `7`，又跨过去连 `6`），谱面上画成数字上方的弧线。
  两种线要分清：**延音线**——连的是紧挨着且音高相同的音，演奏时合并成一个长音；
  **圆滑线**——跨音或音高不同的连接，只画在谱面上做标记，不改变演奏。
  选中音符时下方会写明每个连接属于哪一种
- **小节线**：按拍号（4/4、3/4、2/4）自动画竖线并标小节号，也可以关掉。
  换行只会发生在小节边界，小节内部不会被拆到两行
- **试听**：用浏览器合成音先听一遍，不用进游戏
- **点击音符**，工具栏的时值/八度/升号会自动切成这个音的值；新输入的音默认是四分音符、中音
- 支持选中后改时值/八度/升号、左右移动、删除
- **反复记号**：选中音符后点「‖: 反复开始」/「:‖ 反复结束」圈出一段，
  导出和试听时会真的把这一段再走一遍（不是只画个记号）。
  只有 `‖:` 没有 `:‖` 时，表示从这个记号反复到曲子结尾，程序会自动补一个淡色的 `:‖` 提示
- **转调**：谱面上写「转 1=B（前3=后5）」这类标记时，选中那一小节里的任意音符点「转调」，
  把括号里那串直接抄进去（填 `前3=后5` 即可），也可以直接填半音数。
  简谱是首调记法，「前 a=后 b」这个关系本身就已经包含了该升降多少半音，不需要知道原调是什么。
  转调会自动对齐到该小节的第一个音生效。导出和试听都会按新调换算音高，超出音域的音自动折回八度。
  算出来的移调量如果超过 6 个半音，程序会提示另一个等价填法（相差一个八度）
- **倚音**：选中音符后点「倚音」弹出面板，在里面选音高（`1`–`7`）、八度、时值（八分/十六分/三十二分）
  和升号，下方显示它实际会占多少 tick / 多少毫秒。面板里还有「删除倚音」，点「取消」不会改到谱子。
  谱面上画成数字左上角的小音符，减时线条数跟着时值走（十六分就是两条）。
  演奏时倚音先响，占的是主音前面的一段时间 —— 按时值算，但最多借主音时值的一半
  （主音太短会自动压短，面板里会提示），所以整首曲子的总时长不变。
  导出时写成一个普通短音（`M5/24` 配十六分倚音 `H1` → `H1/6 M5/18`），演奏器那边不需要任何改动。
  倚音的音高会跟着转调一起移调
- **保存 / 打开**：保存成 `.score.json` 工程文件，下次「打开」就能接着改。
  工程文件里连音线、反复、转调、倚音全都在
- **打开 .dhs**：也能直接打开演奏谱，但只能恢复音符 ——
  连音线、反复、转调、倚音在导出时已经展开成实际音符了（反复段被复制、转调的音高已换算、
  倚音变成了独立的前置音），这四类标记恢复不了。想继续编辑就用 `.score.json`
- **清空**：一键清掉当前谱面（会确认）
- **自动保存**：当前正在编辑的谱子也存在浏览器本地存储里，关掉页面再打开还在
  （换浏览器或清缓存会丢）

工程文件是紧凑格式：只写和默认值不同的字段，一个中音四分音符就是 `{"degree":5}`，
八分休止符是 `{"dur":8,"rest":true}`。读回来会自动补全。

谱面上的记号对照（自上而下）：数字上方的圆点是高八度（两个点竖排就是超高音），
数字下方的圆点是低八度，数字下方的横线是减时线（一条=时值减半，同一拍内相邻同层的音会连成一条），
减时线再往下才是低八度点；数字右边的横杠是增时线（延长一拍），右边的小圆点是附点（×1.5）；
音符之间的竖线是小节线，数字上方的弧线是连音线；
`‖:` `:‖` 是反复记号，音符上方的小字（如 `+11`）是转调标记，
数字左上角的小音符是倚音（它自己的八度点画在它上面，低音则画在下面，
下面的短横是它自己的减时线，底部那条折线指向它所装饰的主音）。

快捷键：`1`–`7` 输入音符、`0` 休止、`#` 升号、`↑``↓` 换八度、`←``→` 换时值、
`Backspace` 删除、`t` 连音线、`Esc` 取消选中。

导出时用 `ticks_per_beat=24`，能表示十六分音符和附点；程序本身对任意值都支持。

## 谱面格式

兼容社区的 `.dhs` 文本格式。事件写作 `音位/持续tick数`：

```text
title=小星星
bpm=96
ticks_per_beat=12

[score]
M1/12 M1/12 M5/12 M5/12 M6/12 M6/12 M5/24
M4/12 M4/12 M3/12 M3/12 M2/12 M2/12 M1/24
```

- **音区**：`L` 低音、`M` 中音、`H` 高音、`T` 超高音，后面跟度数 `1`..`7`
- **升半音**：度数后加 `#`，如 `M4#`
- `T` 只有 `T1`（简谱里 1 上面两个点），写 `T2`..`T7` 会报错
- **休止**：`R`
- **时值**：`/` 后面是 tick 数。tick 时长 = `60000 / bpm / ticks_per_beat` 毫秒。
  默认 `ticks_per_beat=12` 时：12 = 一拍，6 = 半拍，4 = 三连音的一份，3 = 四分之一拍
- `#` 或 `;` 开头的是注释，`[score]` 之前写元信息

音区与修饰键的对应关系：

| 记号         | 按法               | 说明              |
| ---------- | ---------------- | --------------- |
| `L1..L7`   | 左键 + `Z..M`      | 低音区             |
| `L1#..L7#` | 左键 + 中键 + `Z..M` | 低音区 + 半音        |
| `M1..M7`   | `Z..M`           | 中音区             |
| `M1#..M7#` | 中键 + `Z..M`      | 中音区 + 半音        |
| `H1..H7`   | 右键 + `Z..M`      | 高音区             |
| `H1#..H7#` | 右键 + 中键 + `Z..M` | 高音区 + 半音        |
| `T1`       | 右键 + `,`         | 超高音 do（1 上面两个点） |
| `T1#`      | 右键 + 中键 + `,`    | 超高音 do + 半音     |

第 8 键配合高音区修饰就是超高音 do

## 键位配置（harmonica.ini）

程序启动时读它，**不在就按默认值写一份带注释的出去**，
所以第一次运行完就能在程序目录里看到这个文件，里面每项都有说明。

设置页的「键位映射」和「时序」两张卡可以改这些值，点「保存」写回文件。
界面上认的键名和文件里认的完全一样（都走 core 的 `parseKeyName` / `parseButton`），
所以手改文件和界面改是同一套规则 —— 界面上填不进去的，文件里也写不出来。

```ini
[keys]
d1=Z          # 简谱 1..7 对应的按键
d2=X
...
d8=COMMA      # 高音 do（第 8 键），可换成 PERIOD / SLASH / 字母

[octave]
low=left      # 低音区：按住鼠标左键
high=right    # 高音区：按住鼠标右键
sharp=middle  # 升半音：按住鼠标中键

[timing]
mouse_lead_ms=60
note_gap_ms=50
```

时序只有两项，单位毫秒（上面这两个数就是默认值）：

| 项               | 含义                    |
| --------------- | --------------------- |
| `mouse_lead_ms` | 修饰键（降调/升调/半音）提前多少毫秒按下 |
| `note_gap_ms`   | 松开一个音之后，隔多久才按下一个音     |

程序完全按谱面时值发按键：不缩短、不顺延、不延长。

写入用的是 core 的 `Config::to_ini`，它和 `apply_ini` 是一对，
有单测盯着「写出去再读回来必须是同一个配置」—— 这条断了，用户的设置会悄悄丢。

### 漏音排查

实测：在游戏里站着不动时按键一个不漏；转动视角或移动时开始漏音。
按键确实按下去了，游戏就是不出声 —— 这是游戏自己的问题，与本程序无关。

程序侧无解，只能绕开：

1. 演奏时别动鼠标，视角先转到位再开始。目前唯一真正有效的办法。
2. 演奏结束的输入统计可以确认程序这边有没有问题：报了「N 个被系统丢弃」
   是权限问题（本程序和游戏都要以管理员身份运行），显示全部成功就回到上一条。
3. 谱子密的时候降速度能少漏几个音：菜单按 `s`，或 `--speed 80`。治标不治本。

`[octave]` 里的鼠标键位仍然可以改，但那是为了避开游戏本身的功能绑定 ——
低音区按住鼠标左键，如果这时左键是开火，会平添麻烦。这和漏音无关。
某一档设成 `none` 的代价是那一档音区会按中音区发出来，音高不对。

## 实现要点

- **绝对时间轴**：所有动作的时间戳都相对演奏起点计算，不累加 `sleep` 误差，长曲子也不会越吹越飘。
- **修饰键区间合并**：连续同音区的音符合并鼠标键的按下/松开，减少无谓的鼠标事件。
- **同刻排序**：同一时刻按「松开音符键 → 松开旧修饰键 → 按下新修饰键 → 按下音符键」执行
  （`actionOrder`）。把「松开旧修饰」排在「按下新修饰」前面是 2026-09-17 修的那条：
  反过来会让游戏同时看到两组修饰键，整段音高判定作废。
- **修饰键不抢在音符前面动**：降调/升调/半音这三个鼠标键的松开和切换，都等前一个音彻底松开、
  再留 `note_gap_ms` 的余量，否则音符还在响、音高就变了，会发出滑音。
  换音区时本段的**每一个**音都要等修饰键建立起来、并且不早于前一个音的松开 ——
  C++ 重写时补的就是这条：以前只推迟段首，遇到时值比松键间隔还短的密集音，
  后面的音会跑到修饰键前面按下，既串音又按在错误的音区上（`core/tests/tst_player.cpp`
  的 `tinyNotesStillGetReleased` 盯着它）。正常谱子里这条推迟不会发生，总时长不变。
- **单声部**：口琴同时只能出一个音，谱子也按单声部处理。
- **退出即释放**：停止、托盘退出、演奏线程异常收工，每条路径都过一遍 `ReleaseGuard`，
  鼠标键卡在按下状态会让整个系统点不动东西。

## 代码结构

| 文件               | 职责                                       |
| ---------------- | ---------------------------------------- |
| `core/score.*`   | 谱面解析（`.dhs` 文本 → `Song`）                  |
